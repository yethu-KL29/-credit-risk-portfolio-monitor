# Credit Risk Portfolio Monitor

Streamlit dashboard over 5 synthetic bank tables, with two embedded AI features: **Ask the Portfolio** (grounded LLM Q&A) and
**Anomaly detection** (review queue with human decisions).

**Python version:** 3.13.11 (tested; 3.11+ should work).

## Run (3 commands)
```bash
pip install -r requirements.txt
python -m src.build            # ingest -> model -> anomaly flags (about 1 minute)
streamlit run app/app.py
```
(`python -m pytest tests` runs the tests; `python -m src.make_docs` regenerates the two PDFs. The dashboard also auto-builds the data/model on first start if `data/processed/` is missing.)

## LLM API key
Google Gemini is the preferred provider (free key from https://aistudio.google.com/apikey). Set `GEMINI_API_KEY` (default model
`gemini-flash-lite-latest`; override with `ASK_MODEL`). OpenAI also works via `OPENAI_API_KEY` (optionally `OPENAI_BASE_URL`).
Locally: `$env:GEMINI_API_KEY="..."` (PowerShell) or `export GEMINI_API_KEY=...` before `streamlit run`. On Streamlit Community Cloud paste
`GEMINI_API_KEY = "..."` into *App settings > Secrets*. Names are listed in `.env.example`; never commit values. Provider logic is all in `src/llm.py`.

**No key set:** the app still works. "Ask the Portfolio" uses a built-in rule-based parser (same whitelist, same pandas executor, same
declines); only the free-form understanding/wording is less flexible. The sidebar shows `LLM mode: ON/OFF`. If the LLM call fails, the app falls back to the parser automatically.

## Key design notes
- Each child table is aggregated before joining, so the account grain (14,685 rows) is never inflated; the build asserts this.
- Collections events are excluded from the model (they happen *after* delinquency = leakage).
- Dashboard risk scores are out-of-fold gradient-boosting probabilities; per-account drivers use occlusion of feature groups.
- Model signal is moderate (hold-out AUC ~0.66-0.67, Gini ~0.33); the GBM does not beat the logistic baseline - reported honestly.
- Ask the Portfolio: the LLM only translates a question into a validated query spec and (optionally) phrases the result; numbers always come from pandas, and the LLM text is rejected if it contains any number not in the result table.
- Review decisions are stored in a local CSV (ephemeral on free hosting) - production would use a database.

## Deployment
Push this repo to GitHub, create a Streamlit Community Cloud app pointing at `app/app.py`, and add `GEMINI_API_KEY` under Secrets.

## Code layout
```
src/ingest.py   load + audit + join the 5 tables        src/ask.py      Ask the Portfolio logic (parse -> validate -> pandas)
src/model.py    LR + GBM, metrics, scores, drivers       src/llm.py      LLM provider (Gemini / OpenAI), one place
src/anomaly.py  peer + own-history anomaly flags         src/build.py    runs ingest -> model -> anomaly
app/app.py      entry point, sidebar filters, tabs       app/common.py   data loading, formatting, decision storage
app/sections/   one file per dashboard tab               tests/          pytest (join grain, Ask, LLM fallback)
```
